## Implemented work

### 1. Shared activity contract and content

Package: `lib/activity-catalog`.

- Distinct activity types: exercise, asana, mobility drill, conditioning activity and sequence.
- Identity and knowledge are separate from prescriptions and actual results.
- Supported metrics and units include reps, seconds, breaths, distance (m/km/ft/mi), load (kg/lb), sets and rest.
- Rich knowledge fields cover instructions, cues, precautions, modifications, anatomy, movement patterns, laterality, evidence qualification, sources and review status.
- Unknown information is explicit rather than fabricated.
- Stable IDs, schema/content versions, aliases, typed relationships and ordered sequence membership.
- Validation rejects dosage on definitions, invalid units, alias collisions, dangling sequence references, cycles and unsafe automatic-eligibility claims.
- Deterministic text retrieval output; no embeddings.

**Validated starter coverage:**

|---|---:|
| Gym/home/bodyweight exercises | 234 |
| Ashtanga asanas/practice elements | 103 |
| Joint-mobility drills | 35 |
| Conditioning activities | 15 |
| Ordered sequences | 2 |
| Total | 389 |

Sequences do not fill individual-activity quotas; sides and repeated sequence members do not inflate counts.

Source inventory and limitations: `docs/catalog/source-inventory.md`.

### 2. Database, API and maintainer operations

- Catalog schema in `lib/db/src/schema/catalog.ts`, exported through the existing database package.
- Normalized releases, channel pointer, identities, aliases, sources, source links, relationships and sequence membership.
- Search indexes and bounded, validated filters.
- Public read endpoints:
  - `GET /api/catalog/release`
  - `GET /api/catalog/activities`
- Public writes are rejected. Database credentials remain server-side.
- Maintainer CLI: `scripts/src/catalog.ts`.
- Operations include validation, dry-run publication, transactional publication, immutable release checks and pointer rollback.
- Explicit environment selection and independent target-environment confirmation.
- No startup DDL or production schema scripts.
- Development release **1.0.0** published; repeat publication succeeded.
- Development rollback dry run and apply were exercised against the existing 1.0.0 pointer. This confirms that command path, but is not a demonstrated rollback between two distinct published versions.

Operations documentation: `docs/catalog/maintainer.md`.

### 3. Offline and personal-data boundaries

- Validated starter included in the app.
- Whole-release cache write/readback before current-pointer commit; previous release retained.
- Serialized cache installation.
- Failure/incompatible-release handling keeps last-known-good data or starter.
- Library shows version, origin, publication date and update failures, plus refresh.
- Cached releases retain archived references, including after server rollback.
- Catalog hydration precedes local personal-data validation.
- Personal custom activities, routines, schedules, active sessions and history remain local.

Key files: `lib/activity-catalog/src/cache.ts`, `artifacts/adaptive-fitness/lib/catalog.ts`, `artifacts/adaptive-fitness/hooks/useCatalog.ts`.

### 4. Migration and measurements

- Local state schema advanced to 3 while retaining the existing storage key.
- Legacy custom dosage moved into separate presets.
- Exact old local bytes are backed up before migration persistence; saving is blocked if safe migration/storage fails.
- Existing scheduled/history snapshots and numeric values are retained.
- Reps, duration, breath and distance targets are supported through prescription and logging.
- Alternate supported measurements and named sides survive snapshot editing and import/export.
- Planned targets and actual results stay separate.
- Breath counts and distances do not silently become seconds; unknown duration is disclosed.
- Numeric drafts publish immediately, so immediate save and stepping use the displayed value.
- Explicit zero load retains its unit and does not restore an older weighted set.

Key files: `artifacts/adaptive-fitness/lib/domain.ts`, `lib/engine.ts`, `context/TempoContext.tsx`, `components/planner.tsx`, `components/targets.tsx`.

### 5. User-facing integration

- Relevant library/planning/session copy now uses Activity rather than Move.
- Search supports aliases and Sanskrit/English names.
- Added filters for type, muscles, joints, difficulty and supported measurements; expanded equipment vocabulary also reaches profile/adaptation.
- Rich detail component displays review/evidence limits, sources, anatomy, instructions and ordered sequence members.
- Routine, date and mid-session additions include target editing.
- Sequences expand into ordered constituent targets with repetitions and sides retained.
- Custom activities support the shared schema and user-authored/unreviewed status, with archival.
- Basic custom editing is supplemented by a strict structured-JSON editor for the full schema. This is functional implementation, not yet browser-verified usability.
- Newly authored catalog activities are not automatically recommendation-eligible. Unknown loading is not accepted as safe against exclusions.

## Evidence and content limitations

These limits must remain visible in the final delivery:

1. The 35 mobility entries comprise **3 sourced CARs identities and 32 general-mobility drills**. Additional joint-specific CARs variants were not invented to meet a count.
2. Broad Ashtanga identity/context is source-backed, including Intermediate and Advanced elements, but advanced entry/exit technique has not been independently verified. Unknown execution/modification fields and instruction-needed flags remain.
3. Review is AI-assisted editorial/source-identity review, not clinical verification or independent expert technique approval.
4. Many detailed loading, secondary-muscle and laterality fields remain unknown.
5. Original wording and factual references are used; no copied charts, licensed programming or competitor media are included.
6. Legacy generated-session definitions remain for compatibility. They do not contribute to sourced coverage or gain new review status retroactively.
7. No claim of exhaustive Ashtanga coverage, universal sequencing, Kinstretch affiliation, certification or medical benefit.
